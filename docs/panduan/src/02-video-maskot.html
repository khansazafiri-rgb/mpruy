1. Gambaran besar dan alur kerja

Kamu menulis naskah per adegan. Kit mengubahnya menjadi suara, menggambar tiap frame di Chromium (browser tanpa layar), lalu ffmpeg menyatukan gambar dan suara menjadi MP4. Semua berjalan di mesinmu sendiri. Tidak ada API berbayar, jadi tidak ada token yang terpakai.

Yang kamu dapat dari satu perintah

  • .mp4 (H.264 + AAC) siap unggah. Format 16:9, 9:16, atau 1:1.
  • .srt takarir dengan teks persis seperti naskah, bisa dipakai di editor atau diunggah ke platform.
  • .jpg thumbnail dari momen terbaik adegan pertama.
  • Untuk iklan: stem terpisah (suara, efek, musik, campuran) supaya bisa diganti satu per satu di editor.

Mengapa tidak memakai generator video AI?

Generator video cenderung mengubah wajah dan bentuk maskot dari frame ke frame, dan teks di layar sering rusak. Kit ini menggambar ulang SVG Kori yang asli di setiap frame, jadi karakternya konsisten, teksnya tajam karena berupa teks HTML biasa, dan hasilnya bisa diulang persis sama. Kekurangannya: geraknya "kartun potongan" (flat 2D), bukan animasi sinematik. Untuk iklan edukasi ini justru itu gayanya.

3. Menyiapkan server atau laptop

Kebutuhan minimal

  • Ubuntu 22.04/24.04 (atau Debian). Laptop Mac/Windows juga bisa dengan WSL; panduan ini memakai Linux.
  • CPU 4 core dan RAM 8 GB cukup. Render video memakai Chromium, jadi RAM 8 GB lebih nyaman daripada 4 GB. GPU tidak diperlukan.
  • Ruang disk sekitar 3 GB (Chromium, model suara 63 MB, frame sementara).
  • Node.js 20 atau lebih baru, ffmpeg, Python 3 dengan venv.

Langkah

  1. Ambil kodenya dan masuk ke folder kit:
    git clone https://github.com/khansazafiri-rgb/mpruy.git
cd mpruy/brand/video
  2. Jalankan pemasang (butuh sudo untuk paket sistem, internet sekali untuk mengunduh):
    bash scripts/setup.sh
    Ini memasang ffmpeg, membuat lingkungan Python berisi Piper, mengunduh suara Indonesia (±63 MB) dari Hugging Face, lalu memasang Playwright dan Chromium.
  3. Cek semua prasyarat:
    npm run check
    Semua baris harus berawalan "ok". Baris "GAGAL" menampilkan perintah perbaikannya.
  4. Dengar satu kalimat:
    npm run say -- "Halo, aku Kori. Selamat datang di MEDCOEL."
    Hasilnya build/say.wav. Layar menampilkan teks yang benar-benar dibacakan setelah kamus pelafalan diterapkan.

Server tanpa layar (VPS) aman: Chromium berjalan headless. Jalankan di VPS yang sama dengan MEDCOEL boleh, tetapi render memakai CPU penuh beberapa menit. Sebaiknya jalankan di luar jam ramai atau di mesin terpisah.

4. Mengetes suara dan melatih pelafalan

Mesin suara membaca teks seperti ejaan Indonesia. Nama merek, singkatan, dan istilah medis sering terbaca salah. Kit punya kamus pelafalan di lexicon.json: kiri tulisan di naskah, kanan ejaan yang dibacakan. Teks di layar dan takarir tidak berubah; hanya yang diucapkan.

brand/video/lexicon.json (cuplikan)
{ "words": {
    "MEDCOEL": "Med koel",
    "FK": "ef ka",
    "SpO2": "es pe o dua",
    "mmHg": "milimeter air raksa",
    "PDF": "pe de ef" },
  "slash": " per ",
  "percent": " persen" }

Cara menyetel kata baru

  1. Buat beberapa ejaan untuk didengar:
    npm run lab -- "MEDCOEL" "Med koel" "Med-koel" "Medikoel" "Med ko el"
    Berkas suara muncul di build/lab, satu per varian.
  2. Dengarkan, pilih yang paling pas di telinga orang Indonesia (minta satu-dua temanmu mendengar juga).
  3. Tulis pilihanmu di lexicon.json, simpan, dan jalankan lagi npm run say.

Pencocokan kata memperhatikan huruf besar-kecil dan memproses kata yang lebih panjang lebih dulu. "FK" tidak ikut berubah di dalam kata lain seperti "FKUI".

5. Menulis naskah yang enak didengar

Naskah video berbeda dengan teks bacaan. Aturan yang terbukti membantu di iklan 75 detik:

  • Satu ide per kalimat, maksimal sekitar 18 kata. Kalimat panjang dengan banyak anak kalimat terdengar datar.
  • Hitung durasi dari huruf: kecepatan bicara sekitar 16-19 huruf per detik. Shot 4 detik hanya muat sekitar 55-65 huruf. Shot 5 detik muat sekitar 75-85 huruf.
  • Eja angka dan simbol yang mau diucapkan: tulis "hampir empat puluh ribu" di naskah suara, sementara layar boleh menampilkan "38.400".
  • Hindari singkatan yang tidak ada di kamus, atau tambahkan ke kamus.
  • Beri jeda di akhir shot (kit menyisakan sekitar 0,15 detik di awal dan akhir).

Menyesuaikan suara ke durasi shot (mode "pas")

Untuk iklan dengan durasi per shot yang sudah ditetapkan, ad/voice.mjs membuat suara tiap shot lalu memastikannya muat:

  1. Buat suara dengan kecepatan normal. Jika lebih panjang dari jendela shot,
  2. percepat sedikit lewat pengaturan Piper (lengthScale turun sampai 0,8, makin kecil makin cepat),
  3. bila masih kepanjangan, percepat dengan ffmpeg (atempo, maksimal 1,3x).
  4. Bila masih melebihi, skrip menandai baris itu MELEBIHI. Solusinya mempersingkat kalimat atau memperpanjang shot.

Percepatan di atas sekitar 1,2x terdengar terburu-buru. Karena itu di iklan, baris shot 4 yang aslinya 93 huruf untuk 4 detik dipersingkat untuk suara draf, dan shot 2 memakai percepatan 1,2x. Untuk suara final, pertimbangkan memperpanjang shot atau memangkas kalimat.

6. Membuat video pertama

Contoh naskah sudah ada di scenes/kenalan-kori.json (5 adegan: sapaan, fitur, satu soal latihan, "gratis", ajakan). Jalankan dulu versi draf (cepat, setengah resolusi):

npm run video -- scenes/kenalan-kori.json --draft

Kalau naskah dan suaranya sudah pas, buat versi penuh dan versi vertikal:

npm run video -- scenes/kenalan-kori.json
npm run video -- scenes/kenalan-kori.json --format 9:16

7. Maskot: gerak, ekspresi, dan sinkron mulut

Kori, Kila, dan Nilo dipakai apa adanya dari berkas SVG di apps/web/src/mascots, sumber yang sama dengan situs web. Kit tidak menggambar ulang atau mengubah desainnya.

Lapisan yang bisa digerakkan

KelasBagian
.mc-floatSeluruh badan (melayang, miring, melompat)
.mc-arm-rightLengan kanan (melambai)
.mc-eyes-normal / .mc-eyes-happyMata biasa (berkedip) / mata senyum
.mc-mouth-normal / -happy / -thinkTiga bentuk mulut
.mc-sparkKilau kecil di daun

Sinkron mulut

Kit membaca kenyaringan suara tiap 1/30 detik, menormalkannya, menghaluskannya, lalu membuka mulut Kori sebanding dengan kenyaringan itu (mulut tertutup saat hening). Ini bukan sinkron fonem ("a, i, u"), tetapi untuk gaya kartun potongan hasilnya cukup meyakinkan dan tetap sama setiap kali dirender.

Aturan agar karakter tetap setia

  • Hanya geser, putar kecil, dan skala seragam. Peregangan (squash/stretch) maksimal sekitar 5-8%.
  • Jangan menambah tangan atau kaki baru, jangan menggambar ulang wajah, jangan membuatnya berbentuk manusia.
  • Properti (kaca pembesar, tanda seru, kilau) digambar terpisah di sekitar maskot, bukan menempel pada SVG-nya.
  • Kila dan Nilo muncul sebentar untuk adegan komunitas; Kori tetap tokoh utama.

8. Musik, efek suara, dan campuran akhir

  • Efek suara iklan disintesis sendiri oleh ad/audio.mjs (pop, whoosh, ketukan, kertas, stempel, ding, kilau). Tidak ada berkas pihak lain, jadi aman soal hak cipta.
  • Musik latar juga buatan sendiri: bantalan akor, petikan sederhana, dan detak ringan di 100 BPM. Cukup sebagai latar rendah. Kalau mau musik yang lebih kaya, pakai musik berlisensi (misalnya dari perpustakaan audio yang mengizinkan pemakaian iklan) dan masukkan lewat --music.
  • Campuran: suara utama di atas, musik direndahkan dan otomatis turun lagi saat ada suara (sidechain ducking), efek ringan, lalu penyeragam kenyaringan sekitar -15 LUFS dengan batas puncak -1,5 dB.

Stem terpisah (out/stems/voice.wav, sfx.wav, music.wav, mix.wav) memudahkan editor memperbaiki satu lapisan tanpa merender ulang semuanya.

10. Contoh nyata: iklan 75 detik "Kirim PDF soalmu"

Iklan vertikal 1080×1920, 30 fps, tepat 75 detik, 16 shot berdurasi 3-5 detik. Gaya: potongan datar 2D, mint/krem/biru tua dengan aksen emas. Kori dipakai apa adanya. Teks di layar dan takarir berupa teks HTML (bukan hasil generator gambar). Cuplikan layar adalah rekaman aplikasi MEDCOEL yang sungguhan, dimasukkan ke kartu UI bergaya.

Alur pembuatan

LangkahPerintahHasil
1. Rekam layarnpm run ad:recordKlip layar sungguhan (Chat Admin, daftar mata kuliah, latihan, halaman admin) di ad/clips
2. Pecah framenpm run ad:framesJPG 30 fps per klip
3. Suara drafnpm run ad:voicevoice.wav dipas ke tiap shot, timeline, .srt
4. Efek dan musiknpm run ad:audiosfx.wav, music.wav
5. Gambarnpm run ad:renderVideo tanpa suara 1080×1920
6. Gabungnpm run ad:muxMP4 akhir + stem di ad/out

Rekaman layar yang sungguhan

  • Direkam dari web yang berjalan lokal dengan data contoh (scripts/seed-demo.mjs), bukan dari server produksi, supaya tidak ada data pengguna nyata di video.
  • Perekam memakai Chromium dengan ukuran ponsel (390×844, kepadatan 2×), menambahkan riak sentuhan emas di titik ketukan, dan menyembunyikan angka uji coba seperti "0/6 soal" agar tidak bertabrakan dengan klaim iklan.
  • Setiap klip membawa penanda waktu (misalnya saat PDF dipilih), sehingga adegan memotong tepat pada momen yang dibutuhkan.

Hal-hal yang sengaja dijaga

  • Tidak ada klaim bahwa PDF diproses seketika. Shot 9 menampilkan pemeriksaan manual oleh admin, dan shot 10 baru menampilkan "diolah" setelah label persetujuan admin.
  • Tidak ada janji hasil klinis atau nilai ujian.
  • Tidak ada angka palsu di shot 15 (hanya ilustrasi bank soal yang bertambah).
  • "38.400 soal" ditampilkan sesuai brief. Angka ini belum bisa diverifikasi dari lingkungan pengembangan (data dev hanya berisi 17 soal contoh; 38.400 sama dengan 384 bab × 100 soal, yang bisa jadi target, bukan jumlah tayang). Sebelum iklan tayang, cek angka asli di /api/medcoel/stats produksi dan ubah di ad/stage-ad.html (hitungan) dan ad/ad.json (judul dan naskah).

Mengganti suara draf dengan suara final

mkdir rekaman             # isi s01.wav ... s16.wav (satu berkas per shot)
node ad/voice.mjs --use rekaman/
npm run ad:render         # hanya perlu bila timeline berubah
npm run ad:mux

Rekaman tiap shot ditempatkan di awal shot (+0,15 detik). Jika rekamanmu lebih panjang dari shot, perpendek kalimatnya atau perpanjang shot di ad/ad.json.

11. Suara yang lebih bagus: rekaman sendiri atau mesin lain

A. Rekam suara sendiri (paling aman dan paling hidup)

  • Rekam di ruangan sempit berkarpet atau lemari berisi baju; jarak mulut ke mikrofon sekitar sejengkal.
  • Satu kalimat naskah = satu berkas WAV atau MP3. Beri nama s01.wav, s02.wav, dan seterusnya.
  • Di scenes.json (video biasa) tulis "audio": "rekaman/s1.wav" pada adegan itu; untuk iklan pakai --use.

B. Mesin lain lewat perintah

Kit bisa memanggil perintah apa pun yang mengubah teks menjadi berkas audio. Atur dengan variabel lingkungan TTS_COMMAND dan set "voice": {"engine": "command"} di naskah. {in} diganti berkas teks, {out} berkas hasil:

export TTS_COMMAND='mytts --text-file {in} --out {out}'
npm run video -- scenes/kenalan-kori.json --draft

Contohnya skrip kecil milikmu yang memanggil API resmi Azure atau Google dengan kunci yang disimpan di server (jangan di repositori). Itu memakai kuota layanan, jadi bukan lagi "tanpa token", tetapi kualitasnya lebih natural.

C. Meningkatkan hasil Piper

  • Pecah kalimat panjang menjadi dua dan beri tanda baca yang jelas (koma, titik).
  • Tulis angka sebagai kata di naskah suara.
  • Tambahkan kata sulit ke kamus pelafalan.
  • Perlambat sedikit ("lengthScale": 1.05) untuk narasi yang lebih tenang.

13. Etika, hak cipta, dan batas klaim

  • Suara: jangan meniru suara orang tanpa persetujuan tertulis. Cek lisensi mesin dan data suara sebelum dipakai komersial (bagian 2).
  • Musik: pakai musik buatan sendiri atau berlisensi untuk iklan. Musik populer tidak boleh dipakai tanpa izin.
  • Konten soal: jangan menampilkan isi soal milik kampus atau penerbit yang belum disetujui untuk tayang. Pada iklan, kartu soal berupa kerangka tanpa isi, dan rekaman latihan memakai soal contoh buatan sendiri.
  • Data pengguna: rekam layar hanya dari lingkungan dev dengan akun contoh. Cek frame akhir untuk nama, foto, atau nomor yang tidak seharusnya terlihat.
  • Klaim: jangan menjanjikan nilai, kelulusan, atau hasil klinis. Jangan menyiratkan proses PDF berlangsung seketika. Pada iklan, proses ditunjukkan melalui pemeriksaan manual oleh admin, dan estimasi waktu di aplikasi hanya perkiraan, bukan janji.
  • Transparansi: beberapa platform mewajibkan label untuk konten yang dibuat atau dimodifikasi AI. Suara sintetis dari Piper termasuk konten buatan; cek kebijakan platform dan beri label bila diminta.

Kamu membantu aku memasang "kit video MEDCOEL" di server Ubuntu milikku.
Repositori: https://github.com/khansazafiri-rgb/mpruy (folder brand/video).

Lakukan berurutan dan berhenti bila ada langkah gagal:
1. Cek versi Ubuntu, Node.js (butuh 20+), ffmpeg, python3-venv, RAM, disk.
2. Clone repositori, masuk ke brand/video, jalankan: bash scripts/setup.sh
3. Jalankan: npm run check  (semua harus "ok")
4. Jalankan: npm run say -- "Halo, aku Kori. Selamat datang di MEDCOEL."
   lalu bantu aku mendengarkan hasilnya (build/say.wav).

menyimpan kunci rahasia di repositori, dan tanya aku sebelum menjalankan
