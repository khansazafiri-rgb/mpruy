# Brain MRI — SRI24 tissue-only private-review candidate

This is a **technical fallback candidate**, not a clearance decision or a production-approved release. It removes the LPBA40-derived region labels from the **generated candidate payload**, while retaining SRI24 T1 and the publisher-supplied three-class tissue map (CSF, grey matter, white matter) for subsequent rights, privacy, terminology and medical review.

## Why this branch exists

MEDCOEL received a refusal of a licensing exception for the LONI LPBA40 atlas. The LPBA40-derived label volume and table remain **BLOCKED** in the committed rights ledger. A free educational website does **not** override LONI's research-only license.

SRI24's T1 atlas and tissue map have a separately documented CC BY-SA 3.0 notice, but all exact-file rights and medical/privacy reviews are still pending. This candidate is deliberately not linked to an approved registry asset or commercial release and cannot activate `brain-mri` in the canonical catalog.

## Building locally, if you have the legitimate private SRI24 archives

Requires only the **official** `sri24_anatomy_nifti.zip` and `sri24_tissue_nifti.zip` archives, at the existing gitignored `local-data/studio-resources/raw/sri24/` path. The preparation tool fails if their known SHA-256 digests do not match. It **does not read the labels archive**.

```sh
node apps/studios/tools/prepare-brain-mri-tissue-only.mjs
node apps/studios/scripts/build-all.mjs --only brain-mri --private --sri24-tissue-only
node --test scripts/studio-tissue-only.test.mjs
```

The output data source lives at `local-data/studio-resources/build/brain-mri-sri24-tissue-only/`. There is no automatic download and no network access required. **Do not** run `--private` alone and assume a no-LPBA40 candidate: it still uses the original legacy private resource path for reproducibility. The new CLI flag is mandatory and only works with `--private --only brain-mri`; missing prepared candidate data fails instead of falling back to a fixture.

The candidate contains:
- `data/t1.nii.gz` and `data/labels-tissue.nii.gz` (official SRI24 volume and three tissue classes, with matched affine/grid);
- `data/labels-tissue.json` with three descriptive tissue names, not cortical-region names;
- `data/NOTICE-SRI24.txt`, `data/LICENSE-SRI24.txt` and `data/dataset.json` with PRIVATE_REVIEW status;
- `server/challenge.json` with three tissue-class questions, **not** handed to the browser by the secure release delivery route;
- `provenance.json` and exact output hashes in the private workspace.

The existing viewer's Guided checks are reused and target grey matter rather than a cortical structure. The Challenge overlay paths are explicitly restricted in `studio.config.json`. These questions **remain unreviewed** and must not be made public.

**Important limitation:** the default resource manifest generated by `build-studio-manifest.mjs` inventories the full committed registry, so it may *mention* blocked asset identifiers as metadata; this does not place the LPBA40 bytes inside the candidate payload or approve the candidate. Before any live release, create a source/evidence-clean per-release registry binding and verify every manifest reference, the asset inventory, and the B1 receipt gate. The original pipeline, exact-file hashes and 46/54 reproducibility ledger remain unchanged.

## Acceptance gates after development

1. Run preparation against authorized exact official files; retain SHA-256 logs and review actual generated bytes. This branch does not claim that run has happened.
2. Confirm no third-party parcellation volume, LUT, derived screenshots, leaked answer keys, or client-readable hidden labels are shipped.
3. Rights reviewer resolves SRI24 exact-file CC BY-SA 3.0 and notice/ShareAlike requirements.
4. Medical/terminology reviewer checks segmentation, intensity class labels, crosshair prompts, and all challenge coordinates and answers.
5. Privacy reviewer signs the exact released bytes, despite source being a population template.
6. Map only independently reviewed assets into a new exact build and resource manifest, with no blocked LPBA40 dependency; run B1 inspector.
7. Test authenticated delivery, challenge restrictions, and browser interactions in isolated staging before any user access.

If review fails, retain this as a technical private-review variant only. A future Harvard–Oxford dataset can be researched separately, with precise atlas license, source hash, spatial transform and medical review; do not silently substitute labels or bundle NC FSL software.
