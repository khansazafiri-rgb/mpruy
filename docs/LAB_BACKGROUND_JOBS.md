# MEDCOEL Lab background jobs

The admin starts **OCT Retina Asset Acquisition** with one short API request. PocketBase stores a `lab_jobs` record and returns immediately. A dedicated, non-root systemd worker polls this queue. Closing Safari, SSH or the laptop does not stop a job. The worker uses only known code paths; job JSON cannot contain commands, URLs, output paths or shell arguments. The first supported definition is `dataset_acquisition/octmnist` at 224 px. The job key `octmnist-224-v1` prevents duplicate heavy runs. The model also reserves `media_registration` and `authoring_generation` types for later predefined pipelines.

The worker persists status (`queued`, `running`, `waiting_retry`, `completed`, `failed`, `cancelled`), stage, item counts, attempts, error summary, result and completed-stage checkpoints. On startup it returns interrupted `running` jobs to `waiting_retry`; it never treats them as successful. One worker claims at most one heavy job. systemd restarts it after a crash, and the same persistent job continues. Cancelling a queued job is immediate; a running job stops cooperatively at its next checkpoint, leaving an unverified `.part` download for a later explicit retry. Failed jobs can be retried. Registration uses stable keys and skips matching existing media, so a crash after 25/32 assets resumes with the remaining seven. A key owned by another source fails loudly.

The OCT pilot downloads from the fixed official Zenodo URL into a private cache. It checks free disk against the expected remaining archive bytes plus 2 GiB reserve, resumes `.part` with HTTP Range when supported, verifies the MedMNIST MD5 **before** promoting the archive, and selects/exports only 20 learning plus 12 practice images with zero overlap. A server that ignores Range causes a safe full restart of the unverified partial. A checksum mismatch quarantines the bad archive as `.npz.invalid` and fails the job. The job creates an unverified draft source, uploads 32 draft media files through the validated admin API, generates authoring JSON and validates it. The completed result is **ready for human review**, never published. The source licence `verified` and dataset policy `reviewed` remain false until a human checks them. Draft media can be staged against this draft source; the existing publish checks still require a published, verified asset source.

Admin-only endpoints under `/api/medcoel/admin/lab-jobs` provide list, detail, create, cancel and retry. Worker claim/checkpoint/recover routes also require an authenticated MEDCOEL admin account; students cannot read or control jobs. The worker's credentials belong in `/etc/medcoel/lab-worker.env` with mode `0600` and no credentials in the repository or logs. The UI polls status and shows progress, failure details, retry and the generated JSON. Opening JSON fills the existing authoring editor; the admin must still preview, apply as draft, inspect the module/source/images/answers, then use the separate Review Bundle → Publish All flow.

## Deployment after review and merge

Do **not** run the OCT acquisition as part of deploying this PR. On the VPS, after pulling reviewed `main`, install requirements from `tools/lab-ingest/requirements.txt`, build the web app, and restart PocketBase so the additive migration and hooks load. Ensure the private cache directory is writable by `MEDCOEL` and is not served by Caddy. Create `/etc/medcoel/lab-worker.env` containing `MEDCOEL_ADMIN_IDENTITY` and `MEDCOEL_ADMIN_PASSWORD` for a dedicated MEDCOEL admin account, owned by root with mode `0600`. Copy `deploy/medcoel-lab-worker.service` to `/etc/systemd/system/`, then run `sudo systemctl daemon-reload`, `sudo systemctl enable --now medcoel-lab-worker`, and check `sudo systemctl status medcoel-lab-worker --no-pager`. Job logs are in `sudo journalctl -u medcoel-lab-worker`; never paste credentials or tokens into logs.

The worker must be started only after the PocketBase migration succeeds. Before production use, perform the disconnect/restart checks with a small disposable source or test fixture: queue a job, close the initiating request and SSH, verify progress continues, restart the worker, and verify it resumes from persistent state. The production OCT multi-GB acquisition and publication require separate operational decisions and human review.
