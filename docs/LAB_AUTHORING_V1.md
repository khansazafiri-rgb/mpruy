# MEDCOEL Lab Authoring System V1

Authoring V1 is additive. The existing PneumoniaMNIST, BloodMNIST, PathMNIST, OCTMNIST packs and their student routes remain intact. A new module is stored once in `lab_authoring`; a `placement` puts it in any number of catalog nodes. Each catalog node has an optional parent, so the catalog has no fixed discipline/subject/chapter depth. Chapters and sections belong to the module, not to a placement.

The [machine-readable schema](LAB_AUTHORING.schema.json) and [complete, self-contained JSON example](LAB_AUTHORING_EXAMPLE.json) describe `schemaVersion: 1`. Valid record kinds are `source`, `guide`, `catalog`, `module`, and `placement`. Stable lowercase keys identify every record, chapter, section, block, bank, question and pathway. An authored module contains ordered chapters, sections, blocks, question banks and pathways. A section can have text, images, galleries, side-by-side comparison, identification guide, identification table, callout, source disclosure and practice. The V1 importer rejects unknown block or question types; they can be added through versioned code later, without allowing arbitrary HTML or scripts.

Use **Admin → MEDCOEL Lab → Import Modul JSON**. Paste a bundle, select **Validasi JSON**, read the blocking errors and review warnings, select **Preview Perubahan** to inspect create/update/unchanged changes, then select **Terapkan sebagai Draft**. The primary screen includes **Salin Template**, a link to the schema, **Lihat Asset Tersedia** to copy stable media keys, and **Upload Media**. The preview token and record revisions are checked again in the transaction so a stale preview cannot silently overwrite edits. Applying the same bundle again makes no content changes. To edit one section, include the module key and only the affected chapter/section; existing sibling chapters, sections, blocks, banks and pathways are retained. To update a block or question, reuse its key. V1 does not implement deletion. An omitted item is retained; there is no implicit cleanup.

The admin record list can reload a draft into the editor and download **Export JSON** for a module with its placements. The browser also previews a draft module with the same safe block renderer used by students; practice is disabled in preview. Manual single-record editors and content-pack tools remain in the secondary admin tabs. Source, media, guide, catalog, module and placement records require explicit human review before publish. Publish dependencies in this order: sources, guides and catalog parents, media, modules, then placements. The server checks references and asset licences at publish time. Draft edits do not modify `publishedData`, so students continue to see the previous published revision until the new revision is approved. Student APIs omit answer keys; answers are checked server-side.

To register a source, create a `source` record. `role: "asset"` plus `ingestionAllowed: true` is required before its image can be registered. Asset sources need a verified licence with commercial use and redistribution permitted; an attribution-required licence also needs a citation. `role: "reference"` sources are for educational claims and never grant image ingestion. A source may include `datasetReviewRequired: true` and `policies` keyed by module key, for example `{ "collection": "observasi-visual-dasar", "allowed": true, "reviewed": true, "note": "Scope checked" }`. Restrictions are enforced when publishing that module and cannot grant rights missing from the base asset licence. Source links are HTTPS and are never fetched by the importer.

After publishing an asset source, upload a PNG/JPEG/WebP up to 20 MB in the Aset gambar form, or register one existing HTTPS image URL. Provide a stable media key, title, meaningful alt text and source key. Media remains a draft until human review and publication. Replacing a file requires a new media key; this prevents an existing published module from silently changing its image. Use media keys in image blocks or questions. Uploaded files live in the separate locked `lab_media` collection. External URLs remain externally hosted and must be checked manually for availability. Do not paste private patient data, unverifiable clinical claims, or unlicensed images.

The new student catalog is an additional section on the existing Lab home page. Students open published authored modules at `/lab/modul/{key}`. Published modules can be placed in multiple catalog nodes without duplicating lessons or question banks. Existing Lab navigation, visual lessons, practice and content packs continue to operate.

Operational limits: V1 does not convert existing Lab packs into authored modules, delete records, provide fine-grained collaborative editing, fetch remote URLs, or publish automatically. New medical media and guidance still require a human content and licence review. Local migrations are additive and preserve existing production content; do not roll back by dropping the new collections.
