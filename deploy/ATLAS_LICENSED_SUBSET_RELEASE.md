# MEDCOEL independent educational subset

This is a separate exact-asset product. It does not clear the legacy NC UI,
private HRA/BP4.3 references, CT data, clinical validation or the global legacy
commercial-release gate. The independently authored shell retains MEDCOEL's
green layout, gold selection, system toggles and controls. Source names and
native coordinates are retained; system classification remains provisional.

Build on a workstation with the retained audited source pack and exact ledger:

```sh
node scripts/build-atlas-licensed-subset.mjs independent-source-review-P5BhfB /path/body-1016-rights-ledger.json /path/new-bundle
node scripts/build-atlas-licensed-subset.mjs --verify /path/new-bundle
node scripts/serve-atlas-licensed-subset.mjs /path/new-bundle 4191
```

The builder validates 1,016 model identities against the fixed rights ledger,
checks every source/GLB hash and generates a build-baked asset-set pin. Runtime
checks inventory identity and each model's bytes before GLTF decoding. It copies
only licensed body models, first-party software and attribution into the bundle.
No private inventory approval flags are changed. Browser render and interaction
QC must run against this exact package digest, not an engineering fixture.

## Staging and approval

Use a versioned directory outside the web build. Verify the package again after
transfer. Run the existing verified database/storage backup on the real server;
retain its receipt and restore evidence. The application DB schema is unchanged
by this static viewer release. Preserve the current Caddy configuration and
active viewer target. Validate Caddy configuration before any reload. Existing
private asset 404 containment must remain in place.

```sh
node deploy/atlas-subset-release.mjs stage /path/new-bundle /var/lib/medcoel/anatomy-releases
```

Host the staged release under a protected same-origin staging route or isolated
loopback endpoint. Check desktop/mobile, actual source labels, all 1,016 renders,
highlight/isolate/hide/restore/undo/fade, Guided Learning, Challenge, loading,
retained memory, console/network errors, and unauthorized/private paths.

The activation tool requires an explicit operator-created approval JSON. It must
contain `authorized: true`, the exact `packageContentsSHA256`, operator identity,
the verified production `backupReceiptSHA256`, and true values for
`actualBuildBrowserPassed`, `securityPassed`, `licensePassed`,
`validationAccepted`, `productionBackupVerified`, `stagingHealthPassed` and
`rollbackRehearsed`. These are release prerequisites, not values generated by
the builder. Do not approve unmet checks or infer a clinical sign-off.

```sh
node deploy/atlas-subset-release.mjs activate /var/lib/medcoel/anatomy-releases/DIGEST /var/lib/medcoel/anatomy-viewer /private/operator-approval.json
```

Activation atomically swaps only an existing symlink (or creates a missing one).
It refuses to replace a real active directory. Save its printed `previous`
target. The existing `deploy/anatomy.caddy.snippet` serves the viewer path and
keeps missing assets 404; review its live inclusion instead of replacing the
whole server configuration. Main-site routing/entry must be verified against
the deployed web build before activation.

## Health and rollback

After cutover, check the live viewer HTML, exact inventory pin, sampled model
hashes, main-site launch and application/API health. Confirm private legacy and
unlisted routes return 404 with GET/HEAD/Range. On error, atomically restore the
saved previous target while the observed active digest still matches:

```sh
node deploy/atlas-subset-release.mjs rollback /var/lib/medcoel/anatomy-viewer /path/previous-target DIGEST
```

Recheck viewer and backend health after rollback. Do not roll back the database
for this static release unless a separate validated recovery plan requires it.
No production deployment or backup is implied by a local bundle or rehearsal.

The release-source audit compares all2,234 ISA members and the164 PART-OF
members used by this retained1,016-model release against cryptographically pinned
old raw hashes. It accepts exact bytes or the one known license-comment change;

old/new PART-OF archive comparison. The separate whole-source survey remains
strict and may HOLD an unreviewed publisher archive container revision. The
initial release keeps its retained exact model bytes and historical source pins.

target. Preserve it privately for provenance. Use a prior cleared subset or an
